# CHECKLIST — перед тем как показывать людям

> Каждый пункт здесь оплачен. Ни один не выдуман «для полноты».

Проверяй руками. «Claude Code сказал, что сделано» — не проверка: расхождение между отчётом и реальностью чаще всего случается ровно в разделе «Безопасность».

---

## Окружение

- [ ] `ANTHROPIC_API_KEY` выставлен в проде. Без него эндпоинт отдаёт 503 — и это правильное поведение, но узнать об этом лучше не от пользователя
- [ ] Ключ БД с правами service_role выставлен на сервере и **отсутствует** в клиентском бандле
- [ ] Ни на одном секрете нет префикса `NEXT_PUBLIC_`
- [ ] `VOYAGE_API_KEY` — если собран Этап 2
- [ ] Все миграции применены на прод-базе, не только локально

## База данных

- [ ] RLS включена на всех четырёх таблицах
- [ ] Политики `deny_anon` и `deny_authenticated` существуют, а не только `service_role_all`
- [ ] Индексы на колонках внешних ключей на месте
- [ ] Внешний ключ `agent_conversations.user_id` указывает на реальную таблицу пользователей (TODO в миграции закрыт)
- [ ] `ON DELETE CASCADE` на `agent_messages.conversation_id` — удаление треда не оставляет сирот
- [ ] Типы БД перегенерированы после последней миграции

## Корпус

- [ ] Количество документов в базе совпадает с количеством на входе
- [ ] Три случайные строки открыты глазами: `body_md` полный, `title` не пустой, `slug` уникален
- [ ] Документы, которых в корпусе быть не должно (черновики, чужие продукты, внутренние заметки), исключены явно
- [ ] `is_published` расставлен осмысленно, а не проставлен `true` везде по умолчанию
- [ ] Скрипт заливки работает через upsert: запусти дважды — количество строк не изменилось

## Поиск

- [ ] `buildContext` проверен напрямую на 5–7 реальных вопросах, выдача осмысленная
- [ ] Кириллица не ломается — в регулярке токенизации есть флаг `u`
- [ ] Прямая ссылка «расскажи про документ N» возвращает именно документ N
- [ ] Фильтр доступа применяется **до** отсечения top-N
- [ ] Фрагменты режутся: целые документы в промпт не уходят
- [ ] Каталог строится всегда, включая случай пустого контекста
- [ ] Вопрос без совпадений даёт честный ответ, а не выдуманное содержание документов

## Эндпоинт

- [ ] `runtime = 'nodejs'` и `maxDuration = 60` выставлены — дефолтные 10 секунд большой контекст не переживают
- [ ] Сообщение пользователя сохраняется **до** вызова модели
- [ ] `system` — массив блоков с `cache_control`, не строка
- [ ] Каталог в `system`, не в сообщении пользователя
- [ ] `temperature`, `top_p`, `top_k` в запросе отсутствуют
- [ ] Prefill не используется
- [ ] `max_tokens` ≥ 2048 либо мышление выключено явно
- [ ] Лимит длины входящего сообщения — 2000 символов, проверяется до всего остального
- [ ] Ошибки модели не проходят наружу в исходном виде
- [ ] Источники нормализованы: наружу едут только `kind`, `slug`, `title`

## Память

- [ ] История ограничена (20 сообщений), а не читается целиком
- [ ] `generateTitle` вызывается через `void` и не блокирует ответ
- [ ] `generateTitle` первой строкой проверяет уже проставленное название
- [ ] Кэш ответов работает только на первом сообщении треда
- [ ] **Уровень доступа входит в ключ кэша**
- [ ] Кэш читается с проверкой `expires_at`
- [ ] `hit_count` инкрементируется при попадании

## Безопасность — проверять лично

- [ ] `GET` с чужим `conversationId` возвращает 404. Проверь: возьми id чужого треда и запроси его своим токеном
- [ ] Пользователь с низким уровнем доступа не получает ни фрагментов, ни пересказа закрытых документов. Проверь на живом вопросе, метящем прямо в закрытый документ
- [ ] Тот же вопрос от пользователей с разными уровнями доступа даёт **разные** записи в кэше, а не одну на двоих
- [ ] Клиентские компоненты не импортируют admin-клиент БД
- [ ] В логи не пишутся ключи и полные тела запросов

## Экономика

- [ ] На втором запросе подряд `cache_read_input_tokens > 0`. Если ноль — кэш не работает, чини до релиза
- [ ] Повтор вопроса в новом треде возвращает `cached: true` с нулевым расходом
- [ ] Прикинута месячная стоимость: `пользователи × вопросов в день × 30 × цена запроса`
- [ ] Есть представление, что делать при всплеске: лимит запросов на пользователя, дневная квота или хотя бы алерт

## Качество ответов

- [ ] Ответ по документу содержит информацию из документа и ссылается на него
- [ ] Follow-up «а подробнее?» остаётся в теме
- [ ] Документ из каталога, не попавший в top-N, не объявляется несуществующим
- [ ] Ответы укладываются в разумную длину — не эссе на каждый вопрос
- [ ] Есть путь эскалации: куда идти пользователю, если агент не помог

## Код

- [ ] `npx tsc --noEmit` проходит
- [ ] `any` в продовом коде отсутствует
- [ ] Нет TODO и заглушек
- [ ] Временное логирование токенов убрано
