# RAG-агент с памятью — сборочный комплект для Claude Code

Это не статья «что такое RAG». Это **рабочая спецификация системы**, которая крутится в проде: AI-наставник внутри платформы курса AI-Архитектор. Ты кладёшь эту папку в свой проект, говоришь Claude Code «собери по MANUAL.md» — и получаешь агента, который отвечает по твоим материалам, помнит разговор и не разоряет тебя на токенах.

## Что получится

Агент, который:

- **отвечает по твоим данным**, а не по своим фантазиям — релевантные куски твоих документов подмешиваются в запрос;
- **помнит разговор** — тред живёт, follow-up «а подробнее?» понимается правильно;
- **помнит между разговорами** — история тредов с названиями, к любому можно вернуться;
- **не платит дважды за одно и то же** — два слоя кэша: повторяющиеся вопросы вообще не доходят до модели, статичная часть промпта кэшируется на стороне Anthropic;
- **отдаёт источники** — под ответом список документов, на которые он опирался, кликабельные;
- **знает границы** — если у пользователя нет доступа к части материалов, он их не увидит и не получит их пересказ.

## Что нужно иметь до старта

| Что | Зачем | Обязательно |
|---|---|---|
| Проект на Next.js (App Router) | API route + UI чата | да |
| Supabase (или любой Postgres) | память агента + корпус знаний | да |
| `ANTHROPIC_API_KEY` | собственно модель | да |
| Свои материалы в текстовом виде | то, по чему агент отвечает | да |
| Claude Code | он это соберёт | да |
| `VOYAGE_API_KEY` | эмбеддинги, только для Этапа 2 | нет |

Если у тебя не Next.js — ядро всё равно переносится: это один серверный HTTP-обработчик плюс четыре таблицы. Заменится слой транспорта, не архитектура.

## Порядок работы

```
1. Скопировать папку rag-agent-kit/ в корень своего проекта
2. Скопировать CLAUDE_TEMPLATE.md → CLAUDE.md в корень (и дописать свои детали)
3. Открыть Claude Code в проекте
4. Идти по PROMPTS.md — шаг за шагом, не пакетом
5. Пройти CHECKLIST.md перед тем, как показывать людям
```

**Не проси Claude Code «сделай всё сразу».** В PROMPTS.md шаги разбиты специально: после каждого есть что проверить руками. Агент, собранный одним промптом, выглядит рабочим и молча врёт в трёх местах из восьми.

## Что в комплекте

| Файл | Что внутри |
|---|---|
| `MANUAL.md` | Архитектура: слои памяти, восемь фаз запроса, как устроен поиск, откуда берётся экономия. Плюс грабли, собранные на живых пользователях. **Главный файл — читай первым.** |
| `SPEC.md` | Спецификация для Claude Code: контракты эндпоинтов, схема, инварианты, критерии приёмки. То, что он будет исполнять. |
| `PROMPTS.md` | Пошаговый протокол: что говорить Claude Code на каждом шаге и что проверять после. |
| `CLAUDE_TEMPLATE.md` | Заготовка правил проекта. Переименовать в `CLAUDE.md`, положить в корень. |
| `migrations/001_agent_memory.sql` | Четыре таблицы: корпус, треды, сообщения, кэш ответов. |
| `migrations/002_knowledge_vectors.sql` | pgvector + функция семантического поиска. Только для Этапа 2. |
| `CHECKLIST.md` | Прод-чеклист. Пункты, каждый из которых мы однажды прошляпили. |

## Два этапа, и первый — не черновик

**Этап 1 — поиск по ключевым словам.** Ноль дополнительной инфраструктуры, ноль расходов на эмбеддинги, работает на корпусе до нескольких сотен документов. Это то, что прямо сейчас отвечает нашим студентам.

**Этап 2 — векторный поиск.** Чанкинг, эмбеддинги, pgvector, косинусная близость. Нужен, когда корпус перерос сотни документов или когда вопросы стали формулироваться смыслом, а не терминами.

Начинать с Этапа 2 «чтобы сразу по-взрослому» — самая частая ошибка. Ты потратишь два дня на пайплайн эмбеддингов, прежде чем увидишь первый ответ. Собери Этап 1 за вечер, посмотри на реальные вопросы живых людей, и только тогда решай, нужны ли векторы. Критерий перехода — в MANUAL.md, раздел «Когда переходить на векторы».

## Границы честности

Это мануал по одной конкретной архитектуре — синхронный запрос-ответ поверх собственного корпуса, с памятью и гейтами доступа. Здесь **нет**: стриминга, мультиагентных схем, Tool Use с действиями (агент отвечает, но ничего не делает), голосового ввода, self-hosted контура под 152-ФЗ. Всё это отдельные слои поверх, и каждый добавляет свой класс проблем.
