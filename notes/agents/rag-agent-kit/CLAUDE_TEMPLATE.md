## AI-агент — жёсткие правила

Полная архитектура: `docs/rag-agent-kit/MANUAL.md`. Контракты: `docs/rag-agent-kit/SPEC.md`.

**Модели (актуальны на август 2026):**
- Основные ответы — `claude-sonnet-5`
- Сложные разборы — `claude-opus-5`
- Названия тредов, классификация — `claude-haiku-4-5`

**Запрещено в запросах к модели:**
- `temperature`, `top_p`, `top_k` — текущие модели отвечают 400
- Prefill (последнее сообщение с `role: 'assistant'`) — 400
- `system` строкой вместо массива блоков — без этого не включается кэш промпта

**Обязательно:**
- `system` — массив с `cache_control: { type: 'ephemeral' }`
- В `system` только то, что не зависит от вопроса (правила + каталог документов). Контекст и вопрос — в `messages`
- `max_tokens` не ниже 2048: у Sonnet 5 мышление включено по умолчанию и расходует тот же бюджет
- Сообщение пользователя сохраняется в БД **до** вызова модели
- Ключ кэша ответов включает уровень доступа пользователя
- При загрузке треда по id — проверка принадлежности пользователю

## База данных

- Изменения схемы — только миграциями, никаких ручных `ALTER TABLE`
- RLS включена на каждой таблице, политики только для `service_role`
- Индексы на всех колонках внешних ключей — Postgres не создаёт их сам
- После каждой миграции — перегенерация типов

## Безопасность

- `ANTHROPIC_API_KEY`, [`VOYAGE_API_KEY`], ключ service_role — только в `.env`, никогда с префиксом `NEXT_PUBLIC_`
- Клиентские компоненты не импортируют admin-клиент БД и не читают секреты
- Лимит длины входящего сообщения — 2000 символов
- В логи не пишутся ключи и полные тела запросов
