# SPEC — RAG-агент с памятью

> Спецификация для Claude Code. Архитектурное обоснование каждого решения — в `MANUAL.md`; здесь только контракты, инварианты и критерии приёмки. При расхождении между этим файлом и привычками модели — прав этот файл.

## Терминология проекта

| Термин | Значение |
|---|---|
| Документ | Единица корпуса знаний: `knowledge_documents` |
| Тред (conversation) | Один разговор пользователя с агентом |
| Уровень доступа | Целое число ≥ 0. Пользователь видит документ, если `user.access_level >= document.access_level` |
| Контекст | Markdown-блок с фрагментами найденных документов, вклеиваемый в сообщение пользователя |
| Каталог | Компактный список всех документов, вклеиваемый в системный промпт |

## 1. Схема данных

Миграции готовы: `migrations/001_agent_memory.sql` (обязательно), `migrations/002_knowledge_vectors.sql` (Этап 2).

Инварианты схемы:

- RLS включена на **всех** таблицах. Политики — только для `service_role`; `anon` и `authenticated` запрещены явно.
- `agent_messages.conversation_id` → `agent_conversations(id) ON DELETE CASCADE`.
- `agent_conversations.user_id` — ссылка на таблицу пользователей проекта. Внешний ключ дописывается под конкретный проект (в миграции помечено `TODO`).
- Индексы на всех колонках внешних ключей — Postgres их не создаёт сам.
- `agent_response_cache.query_hash` — первичный ключ, формат `<sha256>:<access_level>`.

## 2. Контракт `POST /api/agent-chat`

### Запрос

```ts
{
  userToken: string;            // токен/сессия проекта; схема аутентификации своя
  conversationId?: string | null;
  message: string;              // 1..2000 символов
}
```

### Ответ 200

```ts
{
  conversationId: string;
  response: string;             // markdown
  sources: Array<{ kind: string; slug: string; title: string }>;
  cached: boolean;
  gated?: string;               // код гейта, если сработал жёсткий гейт
}
```

`sources` содержит **только** три перечисленных поля. Внутренние `score` и `snippet` вырезаются до записи в БД и до ответа.

### Коды ошибок

| Код | Когда |
|---|---|
| 400 | Нет `message`, длиннее 2000 символов, битый JSON |
| 401 | Токен не разрешается в пользователя |
| 403 | У пользователя нет доступа к агенту |
| 404 | Профиль пользователя не найден |
| 429 | Превышен лимит запросов (если включён) |
| 500 | Не удалось создать тред |
| 502 | Ошибка вызова модели |
| 503 | `ANTHROPIC_API_KEY` не задан |

Тело ошибки клиенту — безопасное: `{ error: 'ai error', message: 'Не удалось получить ответ. Попробуй ещё раз.' }`. Оригинальный текст ошибки уходит в лог, не в ответ.

### Порядок фаз — соблюдать строго

```
1. env + валидация тела + разрешение пользователя
2. получить/создать conversationId
3. жёсткие гейты → короткое замыкание без вызова модели
4. прочитать историю (limit 20) → затем сохранить сообщение пользователя
5. кэш ответов — только при priorMessages.length === 0
6. buildContext(...)
7. anthropic.messages.create(...)
8. сохранить ответ → обновить last_message_at → записать кэш → void generateTitle
```

Обмен местами шагов 4 и «сохранить сообщение» ломает историю: только что записанный вопрос попадёт в собственный контекст.

### Настройки рантайма

```ts
export const runtime = 'nodejs';
export const maxDuration = 60;
```

## 3. Контракт `GET /api/agent-chat`

Параметры: `userToken` (обязательный), `conversationId` (необязательный).

- Без `conversationId` — последний неархивированный тред пользователя.
- С `conversationId` — **обязательна проверка владения**: `.eq('id', requested).eq('user_id', profile.id)`. Не совпало — 404, не 403 (403 подтверждает существование чужого треда).
- Ответ: `{ conversationId: string | null, messages: Array<{role, content, sources, created_at}> }`, лимит 50 сообщений.
- Нет тредов — `{ conversationId: null, messages: [] }` и статус 200. Не ошибка.

## 4. Сборка контекста

```ts
export async function buildContext(
  question: string,
  accessLevel: number,
  maxSources = 8,
  priorUserText = '',
): Promise<{
  context: string;      // '' если ничего не найдено
  catalog: string;      // всегда заполнен, если в базе есть документы
  sources: ContextSource[];
}>
```

### Обязательное поведение

1. **Токенизация:** нижний регистр → `replace(/[^\p{L}\p{N}\s]/gu, ' ')` → split → отсеять `length <= 2` и стоп-слова. Флаг `u` в регулярке обязателен, иначе кириллица вырезается.
2. **Скоринг:** `title × 3 + summary × 1 + body × 2`. Токены короче 3 символов пропускаются. Спецсимволы регулярки в токене экранируются перед `new RegExp`.
3. **Фильтр доступа применяется ДО отсечения top-N.** Не после.
4. **Пиннинг:** прямые ссылки на документ (по номеру регуляркой по сырому тексту; по полному названию при длине названия ≥ 8 символов после нормализации) обходят отсечение top-N. Источник пиннинга — `question + '\n' + priorUserText`. Пиннинг **не отменяет** проверку доступа.
5. **Фрагмент:** окно 1400 символов вокруг первого вхождения токена (2200 для запиненных), с `…` по краям. Целые документы в контекст не попадают никогда.
6. **Дедупликация:** документ, попавший и в пиннинг, и в скоринг, включается один раз — в версии из пиннинга (у неё шире окно).
7. **Каталог** строится **всегда**, даже если контекст пустой, и содержит все опубликованные документы с пометкой недоступных.

### Формат контекста

```
# Релевантные материалы

[Документ 1] <title> (slug: <slug>)
<фрагмент>

---

[Документ 2] …
```

## 5. Кэш ответов

```ts
const cacheable = priorMessages.length === 0;
const queryHash = cacheable ? `${hashQuery(message)}:${accessLevel}` : '';
```

Инварианты:

- `normalizeQuery`: нижний регистр → выбросить не-буквы/цифры → split → отсеять `length < 3` и стоп-слова → **`.sort()`** → join. Сортировка обязательна.
- Уровень доступа в ключе обязателен. Без него — утечка контента между уровнями.
- Читаем только непросроченные: `.gt('expires_at', new Date().toISOString())`.
- При попадании: записать ответ как сообщение ассистента (`tokens_used: 0`), инкрементировать `hit_count`, проставить `last_hit_at`, обновить `last_message_at` треда, вернуть `cached: true`.
- При промахе и успешном ответе: `upsert` с `onConflict: 'query_hash'` и TTL 30 дней.

## 6. Вызов модели

```ts
const response = await anthropic.messages.create({
  model: 'claude-sonnet-5',
  max_tokens: 2048,
  system: [{ type: 'text', text: systemPromptText, cache_control: { type: 'ephemeral' } }],
  messages: [...priorMessages, { role: 'user', content: userMessageWithContext }],
});
```

Жёсткие требования:

- `system` — **массив блоков** с `cache_control`, не строка. Строкой кэш не включается.
- В `system` попадает только то, что не зависит от вопроса: роль, правила, каталог, надстройки по уровню доступа. Контекст и вопрос — в `messages`.
- **Не передавать** `temperature`, `top_p`, `top_k` — текущие модели отвечают на них 400.
- **Не использовать** prefill (последнее сообщение с `role: 'assistant'`) — 400.
- `max_tokens` не ниже 2048: у Sonnet 5 мышление включено по умолчанию и расходует тот же бюджет. Альтернатива — явное `thinking: { type: 'disabled' }`.
- Ответ собирается только из текстовых блоков: `response.content.filter((b) => b.type === 'text')`.
- Расход считается как `usage.input_tokens + usage.output_tokens` и пишется в `agent_messages.tokens_used`.

### Генерация названия треда

```ts
async function generateTitle(db, apiKey, conversationId, firstMessage): Promise<void>
```

- Вызывается через `void` — без `await`, не блокирует ответ.
- Первой строкой — проверка `if (conv?.title) return;` (защита от повторного запуска при попадании в кэш).
- Модель `claude-haiku-4-5`, `max_tokens: 30`.
- Результат: обрезать кавычки по краям, `.slice(0, 80)`.
- Весь код обёрнут в try/catch: падение фоновой генерации не должно попадать в лог как ошибка запроса.

## 7. Жёсткие гейты (опционально)

Нужны, только если есть темы, недопустимые для части пользователей при любых условиях.

- Списки ключевых слов — **узкоспецифичные фразы**, не отдельные общеупотребительные слова.
- Проверка выполняется до вызова модели; при срабатывании модель не вызывается вообще.
- Оба сообщения (вопрос и фиксированный ответ) сохраняются в тред — история должна оставаться связной.
- В ответе — поле `gated` с кодом сработавшего гейта.
- Факт срабатывания логируется: `console.log('[agent-chat] gate', { userId, keyword })`.

## 8. Клиент

- Оптимистичный рендер сообщения пользователя сразу; при ошибке — откат последнего элемента.
- `conversationId` хранится в состоянии и отправляется со следующим сообщением.
- Markdown рендерится тем же компонентом, что и остальной контент проекта.
- Под ответом — карточки источников, ведущие на страницу документа по slug.
- Отдельная обработка 503: понятное сообщение вместо общей ошибки.
- Во время ожидания — индикатор загрузки; повторная отправка заблокирована.

## 9. Критерии приёмки

Функциональные:

- [ ] Вопрос по документу из корпуса → ответ содержит информацию из документа и ссылается на него в `sources`.
- [ ] Вопрос про документ, который есть в каталоге, но не попал в top-N → модель называет тему и предлагает открыть, **не** утверждает, что документа нет.
- [ ] Follow-up «а подробнее?» после вопроса о конкретном документе → ответ остаётся про тот же документ.
- [ ] Прямая ссылка «расскажи про документ 14» → в `sources` именно документ 14.
- [ ] Повтор того же вопроса в новом треде → `cached: true`, расход токенов ноль.
- [ ] Тот же вопрос от пользователя с другим уровнем доступа → **новый** вызов модели, не выдача из чужого кэша.
- [ ] Через 3–5 секунд после первого ответа у треда появляется название.
- [ ] Вопрос, для которого ничего не найдено → честный ответ без выдуманного содержания документов.

Безопасность:

- [ ] `GET` с чужим `conversationId` → 404.
- [ ] Пользователь с низким уровнем доступа не получает ни фрагментов, ни пересказа закрытых документов.
- [ ] Ключи только в `process.env`; префикс `NEXT_PUBLIC_` на них отсутствует.
- [ ] Ошибки модели не проходят наружу в исходном виде.
- [ ] Сообщение длиннее 2000 символов → 400.

Стоимость и стабильность:

- [ ] На втором запросе подряд `usage.cache_read_input_tokens > 0`.
- [ ] `npx tsc --noEmit` проходит без ошибок, `any` в продовом коде нет.
- [ ] Падение модели не теряет сообщение пользователя — оно уже в БД.
- [ ] Ответ на большом контексте укладывается в `maxDuration`.
