## Шаг 2. whisper.cpp (`whisper-cli`) — транскрипция

`whisper-cli` — это бинарь из whisper.cpp (проект ggml-org). Два рабочих варианта установки:

```bash
# Вариант A (проще) — macOS через Homebrew:
brew install whisper-cpp
which whisper-cli          # ожидаемо: /opt/homebrew/bin/whisper-cli

# Вариант B (универсально, любая ОС) — собрать из исходников:
git clone https://github.com/ggml-org/whisper.cpp
cd whisper.cpp && cmake -B build && cmake --build build -j --config Release
# бинарь окажется в build/bin/whisper-cli — добавь его в PATH или используй полный путь
```

Проверка:
```bash
which whisper-cli || ls build/bin/whisper-cli   # ожидаемо: путь найден
whisper-cli --help 2>&1 | grep -i usage         # ожидаемо: строка с usage (стартовый шум ggml/metal — это норма)
```

> На Apple Silicon whisper.cpp автоматически использует Metal — модель `large-v3-turbo` идёт быстро. На Linux/CPU работает тоже, но медленнее; для слабых машин держи fallback-модель `small`.

## Шаг 3. Модель Whisper (ggml)

Скачай модель в свою папку моделей. Рекомендованный дефолт — `large-v3-turbo` (~1.5 GB, лучший баланс скорость/качество), плюс лёгкий fallback `small`.

```bash
MODELS_DIR="$HOME/whisper/models"     # ‹ЗАМЕНИ при желании на свой путь›
mkdir -p "$MODELS_DIR"

# Скрипт-загрузчик идёт в комплекте whisper.cpp (models/download-ggml-model.sh),
# но проще скачать напрямую с Hugging Face:
curl -L -o "$MODELS_DIR/ggml-large-v3-turbo.bin" \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin
# fallback (опционально):
curl -L -o "$MODELS_DIR/ggml-small.bin" \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin
```

Проверка:
```bash
ls -lh "$MODELS_DIR"/ggml-large-v3-turbo.bin   # ожидаемо: файл ~1.5G
# боевой тест на 1 сек тишины — модель должна загрузиться без ошибки:
ffmpeg -f lavfi -i anullsrc=r=16000:cl=mono -t 1 -c:a pcm_s16le /tmp/silence.wav -y
whisper-cli -m "$MODELS_DIR/ggml-large-v3-turbo.bin" -f /tmp/silence.wav -nt 2>&1 | tail -3
# ожидаемо: завершается без "failed to load model"
```

> ⚠️ Запиши `MODELS_DIR` — он пойдёт в раздел «Сводка дефолтов» и во все whisper-команды.

На этом этапе ты можешь делать **cleanup-нарезку** (Фазы 1-6). Для субтитров + motion — продолжай.

## Шаг 6. Hyperframes CLI (субтитры + motion → MP4)

Hyperframes — open-source видео-фреймворк (Apache 2.0): композиция = HTML с `data-*` атрибутами, рендер через headless Chrome → ffmpeg → MP4. Ставить глобально не обязательно — он запускается через `npx`.

Проверка, что CLI поднимается и видит зависимости:
```bash
npx -y hyperframes --version    # ожидаемо: hyperframes vX.Y.Z (тестировалось на 0.7.x)
npx -y hyperframes doctor       # ожидаемо: проверка системных зависимостей; все ключевые — OK
```

`hyperframes doctor` сам проверит Node, ffmpeg и наличие/скачивание headless-Chrome для рендера. Если Chrome не установлен — он подскажет команду (`npx hyperframes browser install` или аналог). Прогони `doctor` до зелёного, потом иди дальше.

> Если `doctor` ругается на Chrome — выполни предложенную им команду установки браузера и перезапусти проверку.

## Шаг 7. Шрифты для субтитров

Субтитрам нужен жирный гротеск. Любой из вариантов рабочий:
- **Inter** (вес 700-900) — бесплатный, https://github.com/rsms/inter/releases — положи `.ttf` в системные шрифты.
- Любой свой брендовый extrabold-гротеск — укажешь его в файле правил субтитров (см. Фаза 7).

Проверка (macOS):
```bash
ls ~/Library/Fonts | grep -i inter    # ожидаемо: Inter*.ttf найден (или твой шрифт)
```
Linux: положи `.ttf` в `~/.local/share/fonts/` и выполни `fc-cache -f`, затем `fc-list | grep -i inter`.

> Если нужного шрифта нет — Hyperframes отрендерит fallback-шрифтом и выдаст warning. Поставь шрифт заранее, чтобы плашки выглядели как задумано.

## Правила монтажа — заполни своими

‹ТВОИ ПРАВИЛА: ниже — пример набора правил одного автора. Перепиши под свой стиль. Это «вшитые дефолты» — агент не должен от них отступать без явной команды.›

> ⚠️ **Cleanup-нарезка по умолчанию ВЫКЛЮЧЕНА.** Если в задаче явно не сказано «сделай cleanup / почисти / убери паузы» — к нарезке не прикасайся. Задачи «субтитры / motion / наложи графику» нарезку НЕ подразумевают: видео остаётся 1:1, графика только поверх. Причина: автоматический cleanup легко режет цельный плотный дубль и оставляет оборванные фразы. Цельный снятый дубль не режем.

**Плотность флоу:** Без паузы между предложениями. Склейка БЕЗ вдоха/воздуха между сегментами. От предложения к предложению — ощущение непрерывности.

**Целостность фраз:** Никогда не резать посреди слова. Фразы должны заканчиваться полностью.

**Вдохи:** Убирать все вдохи между дублями, особенно шумные.

**Слова-паразиты — резать агрессивно:** «эээ», «ммм», «ну», «вот», «типа», «короче», «как бы». Всё вон. ‹ЗАМЕНИ: свой список паразитов, в т.ч. на своём языке›

**Маркеры обращения к зрителю — ОСТАВЛЯТЬ:** «понимаешь», «знаешь», «слушай» — это намеренное вовлечение. ‹ЗАМЕНИ: свои›

**Выбор дубля:** Побеждает последний чистый дубль фразы. Тай-брейк: более сильная формулировка.

**Frankenstein-склейки (склеивание частей разных дублей):** Избегать. Всегда предпочитать ОДИН целый чистый дубль. Склеивать только если ни один дубль не содержит нужного, И явно предупредить пользователя в плане.

**Workflow «сначала согласование»:** НИКОГДА не резать спекулятивно. Всегда:
1. Определить кандидатов-дубли
2. Проверить ре-транскрипцией чанка (границы дублей в полном проходе врут — позонные проходы надёжны)
3. Написать `plan.md` с таймингами + ТОЧНЫМ проверенным текстом по каждому сегменту
4. Вернуть оркестратору на утверждение пользователем
5. Только после явного «go» — выполнить нарезку

## Целевые метрики плотности (откалибруй под свой эталон)

‹ЗАМЕНИ: возьми свой собственный смонтированный ролик как эталон и положи его в `projects/‹эталон›/source.mp4`. Замерь его метрики (см. self-check ниже) и подставь их в таблицу. Цифры ниже — пример с одного 81-секундного ролика; используй как стартовую точку, пока не замерил свой.›

Каждый раз когда cleanup предлагает новую нарезку — ИЗМЕРИТЬ предложенный выход по этим числам ДО возврата плана.

Это **измеримые пороги**, не «на глаз»:

| Метрика | Цель (пример) | Почему |
|---|---|---|
| **WPM (слов в минуту)** | **≥ 190**, идеал 210-230 | Эталон ≈ 213. Ниже 180 — слишком много воздуха. |
| **Доля тишины** (сумма всех пауз / общая длительность) | **≤ 15%** | Эталон ≈ 10%. |
| **Макс. пауза в нарезке** | **≤ 450 мс** | Эталон ≈ 400мс. Любой одиночный разрыв > 500мс — дефект. |
| **Пауз ≥ 500мс** | **0** | Жёсткий потолок. |
| **Пауз 300-450мс** | **≤ 2 всего** | Только на крупных переходах нарративных блоков, не между предложениями. |
| **Пауза между предложениями (один блок)** | **150-300 мс** | Естественный артикуляционный зазор. Больше — резать. |
| **Звук вдоха/выдоха** | **полностью вырезан** | Ноль терпимости. |

### Self-check после построения плана

Перед возвратом `plan.md` оркестратору — просимулировать выход и проверить:

```bash
# Сумма предсказанных длительностей сегментов
TOTAL=<сумма (end-start) по KEEP-сегментам>
WORDS=<сумма слов по KEEP-сегментам из чанк-транскриптов>
WPM = WORDS / TOTAL * 60   # должно быть >= 190 (или твой порог)

# После реального рендера: переизмерить
ffmpeg -i output/clean.mp4 -af "silencedetect=n=-30dB:d=0.15" -f null - 2>&1 | grep silence_
# - пауз >= 500мс -> должно быть 0
# - сумма silence_duration / total duration -> должно быть <= 0.15
```

Если порог не сошёлся: НЕ отдавать. Второй проход уплотнения, выщёлкивая виновные паузы без потери целостности слов.

### Правило склейки дублей

Хороший эталон обычно НЕ сохраняет естественную каденцию диктора между дублями: ведущая и хвостовая тишина каждого дубля **сбривается до 100-200мс перед склейкой**. При построении списка сегментов:

- Для каждого KEEP-сегмента найти пословные границы (первая фонема первого слова → последняя фонема последнего).
- Добавить НЕ больше 80мс аудио-паддинга перед первым словом, НЕ больше 150мс после последнего.
- Следующий сегмент стартует сразу — в финальном рендере между последним словом предыдущего и первым словом следующего должно быть только 150-300мс.

### Правило перехода нарративных блоков

«Нарративный блок» — связный кусок контента (hook / setup / list / CTA). Максимум ДВА перехода в ролике ≤2 мин получают «длинную паузу» (300-450мс). Всё остальное — 150-300мс. Определи блоки в плане и пометь, какой переход получает длинную паузу — только их.

### Протокол сравнения с эталоном

При предложении нового плана cleanup отчёт ОБЯЗАН включать:

```
Прогноз WPM: <N>            (цель: >=190)
Прогноз доли тишины: <X>%   (цель: <=15%)
Прогноз макс. паузы: <Y>мс  (цель: <=450)
Против эталона: <впиши свои числа>
```

Если прогноз не сходится — переделать план, не отгружать.

## Пайплайн — стандартная последовательность

### Фаза 1: ingest (один раз на проект)

```bash
mkdir -p ‹КОРЕНЬ_ПРОЕКТОВ›/<slug>/{chunks,output}
echo "<abs path>" > .../source.txt
ffmpeg -y -i "<src>" -vn -ac 1 -ar 16000 -c:a pcm_s16le audio.wav
```

### Фаза 2: транскрипция + детекция

```bash
# Полный файл (грубо, для нарративной структуры)
whisper-cli -m ‹ПАПКА_МОДЕЛЕЙ›/ggml-large-v3-turbo.bin -l ‹ЯЗЫК› \
  -f audio.wav -oj -of transcript_full

# Пословно (точные границы)
whisper-cli -m ‹ПАПКА_МОДЕЛЕЙ›/ggml-large-v3-turbo.bin -l ‹ЯЗЫК› \
  -f audio.wav -ml 1 -oj -of word_timing

# Карта тишины (паузы между дублями)
ffmpeg -i audio.wav -af "silencedetect=n=-30dB:d=1.0" -f null - 2>&1 \
  | grep silence_ > silences.txt
```

### Фаза 3: анализ зон

«Речевая зона» — регион между длинными тишинами. Обычно содержит 1–N дублей одного контента. Для каждой зоны:

1. Извлечь аудио-чанк: `ffmpeg -ss S -to E -i audio.wav -c copy chunks/<S>-<E>.wav`
2. Ре-транскрибировать: `whisper-cli ... -f chunks/<S>-<E>.wav -nt`
3. Сохранить чистый текст в `chunks/<S>-<E>.txt` с офсетом в имени файла

Критично: полный проход галлюцинирует и сливает дубли. Позонная ре-транскрипция надёжна.

### Фаза 4: построить план

Выбрать ЛУЧШИЙ дубль каждого нужного предложения по чанк-транскриптам. Для точности границ — пословная ре-транскрипция выбранного чанка.

`plan.md` примерно так:

```markdown

Original duration: <s> sec
Target duration: <s> sec

```

### Фаза 5: выполнить (только после «go» от оркестратора)

ffmpeg `filter_complex` с `trim`/`atrim`/`concat`:
- `setpts=PTS-STARTPTS,fps=30` на видео-сегмент
- `asetpts=PTS-STARTPTS,afade=t=in:st=0:d=0.03,afade=t=out:st=DUR-0.03:d=0.03` на аудио-сегмент (30мс фейды от кликов, без тишины между)
- Энкодер: `h264_videotoolbox -b:v 8M` (hardware-accel на Apple Silicon). ‹ЗАМЕНИ: на Linux/Intel или без VideoToolbox — `libx264 -crf 18 -preset medium`›
- Аудио: `aac -b:a 192k`
- `-movflags +faststart`
- Выход: `output/clean.mp4`

После нарезки — ре-транскрибировать `clean.mp4` → `output/clean.srt`.

# Фаза 7: субтитры + motion-графика

После нарезки (или прямо на сыром видео, если нужны субтитры + motion без обрезки) — собрать вылизанную версию с **вшитыми анимированными субтитрами** и **motion-overlay'ами**. Современный путь доставки для Reels / Shorts / TikTok.

> ⚠️ **Субтитры — обязательный слой финального рендера**, не опция. Выключить их можно только при явном «без субтитров» от оркестратора. Субтитры обязаны покрывать ВЕСЬ говорящий текст ролика от первой до последней фразы — без дыр; перед сдачей сверь начало, конец и стыки. Motion-графика — по запросу.

> ⚠️ **Motion — сначала план таймкодов на согласование, потом рендер.** Финальный рендер не создаётся, пока пользователь не одобрил план. Даже если бриф не пишет «согласуй план» — всё равно сначала возвращаешь план человеческим языком (см. ниже), ждёшь «ок».

## Стек (Hyperframes)

- Open-source видео-фреймворк (Apache 2.0). Композиции = HTML-файлы с `data-*` атрибутами, рендер через headless Chrome → ffmpeg → MP4.
- Запуск через `npx -y hyperframes <команда>` (см. онбординг, шаг 6).
- Корень проектов для motion-работы: `‹ЗАМЕНИ: твоя рабочая папка проектов, напр. ~/video-projects/›<slug>/`. Один проект на видео.

## Субтитры — правила вынеси в отдельный файл

**Прочитай `‹ЗАМЕНИ: путь к файлу правил субтитров›` каждый раз перед сборкой субтитров.** Там определи под себя:

- Размер шрифта (напр. кегль 42px, мин 36)
- Ширина плашки (напр. 760px), цвет, border-radius
- Всегда 2-строчная раскладка, авто-сплит длинных сегментов на естественных паузах
- Проход орфо/грамматики после whisper (LLM)
- **Замена бренд-терминологии** — ‹ТВОЙ СПИСОК: как whisper слышит названия → как должно быть написано. Пример: распознанные на слух названия инструментов/брендов → их правильное написание. Подставь свои.›
- Правила акцента (напр. красный): числа, бренды, ключевые эмоциональные слова (макс 3 на группу)

- **Стиль — без импровизации.** Зафиксируй один стиль в этом файле и держись его; новый стиль — только по явному согласованию.

Держи где-то reference-реализацию (`index.html` рабочего примера) — копируй её `<script>` блок (RAW_GROUPS, TERMS, splitIfLong, isEmphasized, GSAP timeline) как стартовую точку. ‹ЗАМЕНИ: путь к своему reference-примеру›

### Покрытие речи субтитрами — без пропусков

Субтитры покрывают ВЕСЬ произнесённый текст от первой до последней фразы — не «местами», не «основное». Перед сдачей: транскрибируй полную дорожку финального рендера, сверь что каждый произнесённый сегмент имеет субтитр, проверь начало и конец ролика и стыки. Дырки в субтитрах = брак.

## Motion-графика — каталог

Motion-блоки визуализируют то, что говорит спикер, на окна 2-5 сек.

**⚠️ Размещение — НАД головой спикера (жёсткое правило для overlay-вставок):**
- Разрешённая зона: верхняя треть кадра (≈ `y: 0..420` на 1080×1920). Над головой, не на лице.
- НИКОГДА: лицо, лоб, глаза, рот. Лицо спикера должно быть видно.
- Альтернатива: нижняя треть НАД субтитрами, если верх занят.
- Обязательная проверка перед рендером: ffmpeg-скриншоты на ключевых таймкодах motion-блоков, визуально подтвердить что плашка не наезжает на лицо. Наезжает — пересчитать координаты.

**⚠️ Два типа б-роллов — overlay vs full-frame:**
- **Overlay-вставка** — мелкий motion/плашка поверх говорящей головы, лицо видно → правило «над головой» выше.
- **Full-frame вставка** — закрывает ВЕСЬ экран на своём таймкоде, головы в кадре нет → визуал заполняет весь кадр 1080×1920 от края до края, сбалансированно сверху донизу. Зажимать в верхнюю треть нельзя — будет пустая нижняя половина.
- Дефолт: б-ролл без пометки «overlay / поверх головы» = FULL-FRAME. Перед сдачей проверь кадром (`ffmpeg -ss` на поздней секунде): заполнены ли верх, середина и низ.

**Стиль-дефолты:** ‹ТВОИ: палитра, шрифт, тайминги анимаций›
- Премиум-минимал (пример): графитовая плашка с тонким контуром 1px белый rgba(0.10), моно-цифра 120-160px (напр. JetBrains Mono) тёплым янтарным `#f5c87a` или мятным `#3CE0A0`. Inter 18-26px для подписей. Контрастный красный `#ff3b30` — только для переходов «было→стало», не дефолт.
- Анимация enter: `power3.out` / `easeOutCubic` 0.5-0.7с, плавно fade+slide. Exit: `power2.in` 0.3-0.4с, чистый fade. Запрещено: bounce, elastic, spring overshoot, кручение.
- Hard kill в конце каждого блока (`visibility: hidden`).

**Каталог** (reference-реализация — в своём `‹ЗАМЕНИ: путь к примеру с motion›`):

| Тип | Когда | Пример триггера |
|---|---|---|
| **counter** | Упомянуто число («15 минут», «700 тысяч ₽») | «за 15 минут это сделал» |
| **callout** | Короткое эмоц. слово требует фокуса («БАН», «БЕСПЛАТНО») | «в итоге потом бан» |
| **cards** (bullet reveal) | Спикер перечисляет 3-5 пунктов | «первое… второе… третье…» |
| **tree** (диаграмма) | Объясняется архитектура / иерархия | «сверху главный, под ним…» |
| **compare** | Сравнение A vs B | «старый способ против нового» |
| **pipeline** | Процесс / шаги потока | «запись → монтаж → публикация» |
| **badge** | Самостоятельный ярлык, который должен «прилипнуть» | «ЛОКАЛЬНО», «FREE», «OPEN SOURCE» |

Для НОВЫХ типов motion — строй в том же паттерне (CSS-класс `mg-<name>`, HTML внутри `#motion-layer`, GSAP IIFE в `<script>` с enter / hold / exit).

## Motion-workflow (когда оркестратор просит motion)

1. **Прочитай транскрипт** из `transcript.json` проекта.
2. **Просканируй сегменты** на кандидатов по категориям (числа → counter; сильные эмоц. слова → callout; списки 3-5 → cards; архитектура → tree; сравнения → compare; процессы → pipeline).
3. **Предложи** оркестратору (всегда — никогда не авто-выбирай больше 2-3 motion без утверждения). Описывай каждый блок ЧЕЛОВЕЧЕСКИМ языком — см. «Язык плана на согласование» ниже.
4. **Жди утверждения** (оркестратор выбирает что реализовать). Помни: одобрение метафоры/идеи ≠ одобрение конкретного визуала. Нет описания темпа/характера движения — запроси его до рендера.
5. **Реализуй** утверждённые: CSS-блок в `<style>`, HTML-элемент в `#motion-layer`, GSAP IIFE перед регистрацией timeline.
6. **Линт**: `npx -y hyperframes lint` (или `npm run check` если в проекте есть скрипт) — 0 ошибок.
7. **Скриншот-проверка** размещения: `npx -y hyperframes snapshot` на таймкодах motion — плашки не на лице.
8. **Рендер**: `npx -y hyperframes render` (или `npm run render`) — MP4 в `renders/`.
9. **Скопируй** финал куда нужно по запросу пользователя.

## Язык плана на согласование (этап «жду go»)

Когда отдаю motion-план оркестратору на approve — описываю каждый блок ПРОСТЫМ ЧЕЛОВЕЧЕСКИМ ЯЗЫКОМ. Пользователь не разработчик motion-графики, он не должен расшифровывать термины. Его задача — посмотреть и сказать «ок / переделай».

Это правило применяется ТОЛЬКО на стадии «жду go». В процессе разработки, в коде, в логах рендера, в `decisions.md` — могу пользоваться любыми внутренними терминами.

### Запрещено в описании плана

- Названия CSS-классов / внутренних компонентов
- Одиночные термины-категории без расшифровки: counter, pipeline, tree, compare, cards reveal, callout, badge
- Технический жаргон motion design: waveform, depth, glow, fade, overlay, stack, pivot, scale-in, slide-in
- Любые ссылки на фреймворк / GSAP / трек-индексы

### Формат каждой точки плана

```
N. t=ВРЕМЯ — название (1-3 слова, что это вообще)
   Что увидит зритель: <простая фраза>
   Где: <верх / центр / низ / справа / на весь экран>
   Когда появляется: <начало блока речи / на ключевом слове / в момент Х>
```

### Примеры замен «жаргон → человек»

| Плохо (жаргон) | Хорошо (по-человечески) |
|---|---|
| glass-stat «2-3 ЧАСА / 2-3 тыс. ₽» | плашка с цифрами «2-3 ЧАСА / 2-3 тыс. ₽» в стеклянном виде вылетает справа |
| cards reveal — 4 карточки | 4 карточки с названиями появляются по очереди по мере того как ты их называешь — каждая всплывает в центре |
| callout «БУМ» | вспышка-надпись «БУМ» красным, на весь экран на секунду |
| badge «21 / 100» + прогресс-бар | значок «21 / 100» с заполненной полоской прогресса в нижнем углу |
| counter-блок 0 → 100к | цифра, которая быстро крутится от нуля до 100 000 |

### SFX в плане — тоже по-человечески

- ❌ «boom.mp3 на 4.4с vol 0.85»  ✅ «глухой удар (как взрыв в кино) на 4.4 секунде»
- ❌ «sparkle.mp3 vol 0.85 за 0.5с до конца»  ✅ «звон-вспышка как финальный аккорд — за полсекунды до кадра „подпишись“»

## Sound Design — библиотека SFX

> ⚠️ **SFX по умолчанию — НЕТ.** Чистый ролик без SFX звучит дороже, чем «приправленный». Добавляй SFX ТОЛЬКО если оркестратор/пользователь явно попросил. Свист/whoosh-переходы между фразами — лучше избегать. Раздел ниже — справочник на случай явного запроса.

‹ЗАМЕНИ: собери свою библиотеку SFX (Pixabay / Mixkit — бесплатные). Положи в `~/sfx/` или свой путь, держи каталог в `sfx-library.md`. См. онбординг, шаг 8.›

| Файл | Когда |
|---|---|
| `ding.mp3` | counters, pop-ups, success |
| `boom.mp3` | callout, большие reveal'ы («БАН») |
| `whoosh.mp3` | cards/slide reveal'ы, переходы |
| `pop.mp3` | tree leaves, мелкие badge |
| `tick.mp3` | пункты списков, тики счётчика |
| `snare.mp3` | compare reveal'ы, X→V переходы |
| `sparkle.mp3` | premium/финальные штрихи |
| `cash.mp3` | money-счётчики |

### Главное правило: МАКСИМУМ 2-3 SFX на видео

Sound design — приправа, не основное блюдо. Если на каждый motion-блок повесить звук — клиповая каша, которая бесит зрителя через 5 секунд.

**Правила выбора:**
1. Пройди по транскрипту и motion-плану, отметь ВСЕ моменты где SFX релевантен по контексту.
2. Отбери максимум 3 — самые важные / эмоциональные / контекстно-обязательные.
3. Если кандидатов 4+ — приоритет (чем выше, тем важнее): деньги → `cash`; драм. слово (БАН/РИСК) → `boom`; сравнение → `snare` на каждой стороне; главное число → `ding`; парад фич/карточек → `whoosh` ОДИН раз на старте; CTA/закрытие → `sparkle`.
4. Не перегружай. 2-3 уже есть — стоп.
5. **Громкость** ‹ЗАМЕНИ: откалибруй на своих сэмплах›: `boom` 1.0, `sparkle`/`cash` 0.85, `ding` 0.7, `whoosh` 0.6, `pop` 0.5, `tick` 0.4.

### Контекстно-обязательные сценарии (если SFX запрошены)

- **Деньги в кадре** (любая сумма) → `cash.mp3` синхронно с появлением числа
- **БАН / РИСК / провал** в callout → `boom.mp3` точно в момент scale-in
- **Финальный CTA** последние 3 секунды → `sparkle.mp3` за 0.5 сек до кадра «подпишись»

Для всего остального (cards reveal, tree, обычные counter) — НЕ добавляй SFX по умолчанию.

**Add to composition** (рядом с `<audio id="a-roll-audio">`, внутри `#root`):

```html
<audio
  id="sfx-counter-15"
  src="sfx/ding.mp3"
  data-start="22.72"
  data-duration="0.15"
  data-track-index="5"
  data-volume="0.6"
></audio>
```

**Критичные шаги настройки (один раз на проект):**
1. Скопируй нужные SFX в папку проекта: `mkdir -p sfx && cp ‹ТВОЙ_ПУТЬ_SFX›/{boom,ding,...}.mp3 sfx/`
2. Используй **относительный путь** `src="sfx/<file>.mp3"` — абсолютные пути дают 404 в рендере.
3. У каждого `<audio>` ОБЯЗАН быть `id` — иначе линт-ошибка и звук молчит в рендере.
4. `data-track-index="5"` — отдельный от голоса (track 2).
5. `data-volume="0.6"` — тише голоса (0.5-0.7; 0.85 для драмы).
6. Несколько SFX могут срабатывать одновременно — фреймворк смикширует.

### Правило матчинга

Применяй иконку при совпадении с любым trigger-словом. Список расширяемый. Близкое по смыслу, но НЕ из списка — НЕ ставь (лучше пропустить, чем мимо). «Подпишись» ≠ «поделись».

### Правила overlay

- Position: `bottom: 250px; right: 60px;` — выше сабов, не пересекается с motion (верхняя треть)
- Size: 200-240px квадрат
- Track index: 6 (отдельный от motion и SFX)
- Длительность блока: 2.5-3 сек
- `mix-blend-mode: screen` чтобы убрать чёрный фон (или предконвертированный WebM с alpha)
- Скопировать в папку проекта, ссылаться через `src="icons/<name>"` (relative)

**Эти иконки НЕ считаются в правиле «макс 3 SFX»** — это визуальный action prompt, не часть SFX-приправы. Не повторяй одну иконку дважды в одном видео.

## Что возвращать для задач с субтитрами/motion

- Путь(и) к отрендеренным MP4
- Резюме линта (ошибки / warning'и)
- Список добавленных motion (таймстамп + тип + контент)
- Список добавленных SFX (таймстамп + файл, если есть)
- Размер файла и длительность
- Любые warning'и для внимания пользователя (fallback шрифтов, overflow раскладки и т.д.)
