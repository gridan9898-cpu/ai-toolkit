# AutoManus — sales-агент через MCP

Платформа для быстрой сборки sales/booking-агента: MCP-сервер `@automanus/mcp-server` + REST API. Заявленный путь — из Claude Desktop / Claude Code задать company name, сайт и e-mail, дальше бэкенд сам парсит сайт и собирает knowledge base агента.

> ⚠️ Всё ниже — **демо автора ролика, не проверено**. Один прогон на примере Calendly не доказывает ни точность, ни безопасность.

## Что в коробке (по демо)

- Research сайта → автосборка knowledge base (тяжёлый JS-рендеринг захватывается не полностью, есть ручное дополнение).
- Каналы: test link, WhatsApp, Web Chat Widget с embed-кодом и preview.
- Dashboard: goals/actions, Inbox с историей диалогов.
- **Lead extraction** — из конкретного диалога собирается структурированный лид: намерение, задача, сегмент, ориентировочная ценность.
- Пополнение знаний на лету — MCP tool `add knowledge` (в демо: добавили booking link, агент начал его отдавать).
- Два пути создания: через MCP из Claude (агент живёт на их сервере, пока не сделан claim по домену — до этого sandbox) и через API-ключ (создаётся сразу в своём аккаунте, claim не нужен).
- Free plan: один задеплоенный агент одновременно.

## Зачем смотреть

Ближе всего к агентской практике: типовой запрос «поставьте нам агента на сайт/в WhatsApp» здесь закрывается за вечер, без своей инфраструктуры. Интересна не платформа целиком, а **три её механики как образец для собственной сборки**: research сайта → KB, structured lead из свободного диалога, виджет как канал.

## Что проверить до любого применения

- Где физически лежат данные клиента и что происходит с ними до claim домена — агент до claim живёт на чужом сервере.
- Цена на объёме, а не free plan с одним агентом.
- Качество KB из сайта клиента на реальном сайте с JS.
- Есть ли экспорт лидов в CRM (иначе Inbox — тупик, а не воронка).
