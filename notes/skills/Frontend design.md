# Frontend design

Центральная заметка для всего, что помогает делать **дизайн в вайбкодинге**: UI, лендинги, дизайн-системы, визуальные варианты, accessibility, frontend-polish и проверку интерфейсов через AI coding agents.

## Главный принцип

**Дизайн — отдельная фаза, а не побочный эффект генерации кода.**

Если в плане разработки нет этапа дизайна, нужно вернуться в план и добавить его до продакшн-компонентов.

Рабочая цепочка:

```text
референсы → дизайн-система / DESIGN.md → мокапы → проверка → реальные компоненты
```

Ключевое правило из курса: **не писать продакшн-код, пока не утверждён дизайн на мокапе**.

## Базовый skill

Установить skill `frontend-design` от Anthropic в текущий проект (`.claude/skills/`, не глобально).

1. Найти официальный репозиторий Anthropic с этим скиллом.
2. Провести [[Аудит skills|аудит безопасности]].
3. Если безопасно — поставить локально.
4. Показать, как его триггерить: по каким ключевым словам Claude сам поймёт, что пора использовать этот скилл.

Триггеры:

- «сделай красиво»
- «собери лендинг»
- «улучши UI»
- «приведи экран к дизайн-системе»
- «проверь типографику / spacing / визуальную иерархию»

Источник в базе: [[04 Sources/Курсы/СмыслоКод - День 2 - Промпты/37 - Установить Frontend Design skill|Установить Frontend Design skill]].

Смежный skill для финальной UI-полировки: [[Make Interfaces Feel Better]] — типографика, hover states, тени, радиусы, оптическое выравнивание, микроанимации.

## Дизайн-системы в Markdown

Из урока [[04 Sources/Курсы/AI-архитектор/01 - Уроки/17 - Проект 3|Работа с дизайном: дизайн-системы и UI/UX через Claude Code]]:

- дизайн-системы удобно хранить в `.md`, потому что Claude/Codex хорошо читают Markdown;
- полезная структура папки бренда:
  - `design.md` — полная дизайн-система;
  - `preview.md` — превью элементов;
  - `visual_catalog.md` — визуальный каталог;
  - `tokens.md` — цвета, типографика, layout;
- референсы можно передавать агенту как обычные markdown-файлы.

### 3 метода работы

| Метод | Когда использовать | Риск |
|---|---|---|
| Drag & Drop | быстрый MVP, не нужна уникальность | дизайн будет почти копией референса |
| Reference + Customize | SaaS, серьёзный продукт, нужен баланс скорости и уникальности | нужно хорошо описать задачу и ограничения |
| Без референсов / через 21st Dev | нужна уникальность с нуля | больше токенов, выше риск «красиво, но бесполезно» |

Рекомендуемый вариант: **Reference + Customize** — взять 2–3 бренда/референса и попросить агента кастомизировать под конкретную задачу.

## Мокапы до разработки

Сначала генерировать **1–2 эталонных экрана**, а не весь продукт:

- Dashboard / главный экран;
- Kanban / рабочий экран;
- pricing / landing section, если проект публичный;
- onboarding / critical flow, если важна конверсия.

Почему так:

- на эталонных экранах видна вся система стилей;
- HTML-мокап без логики дешевле по токенам, чем полноценная разработка;
- проще сравнить V1/V2 и выбрать, что реально работает.

Проверочный вопрос агенту после генерации:

```text
Использовал ли ты 21st Dev / frontend-design / выбранную дизайн-систему в этом мокапе? Покажи, где именно.
```

## Красивое ≠ эффективное

Claude и другие агенты могут делать интерфейс визуально эффектным, но менее полезным.

Проверять каждый важный элемент:

- помогает ли пользователю принять решение;
- не ухудшилась ли информативность графиков/таблиц;
- понятен ли CTA;
- не мешают ли анимации;
- нет ли декоративной бутафории вместо смысла.

Если элемент спорный — просить варианты:

```text
Переработай этот блок и предложи 4 варианта A/B/C/D. Оцени каждый по информативности, читаемости и конверсии.
```

## Кириллица и шрифты

Перед утверждением дизайн-системы проверять русский текст. Не все западные шрифты нормально поддерживают кириллицу.

Безопасные варианты:

| Шрифт | Стиль |
|---|---|
| Inter | современный, нейтральный |
| Roboto | универсальный |
| Open Sans | читаемый |
| Manrope | геометричный |
| Montserrat | брендовый |

Промпт-проверка:

```text
Проверь, поддерживают ли выбранные шрифты кириллицу. Если нет — предложи близкую замену с поддержкой русского языка.
```

## Автоматическая проверка UI

Для валидации интерфейса подключать [[Playwright MCP]] / браузерную проверку:

1. агент открывает локальный проект;
2. проходит ключевой сценарий;
3. проверяет ошибки, наложения, проблемы с кликами;
4. предлагает фиксы;
5. повторяет проверку.

Это особенно важно после крупных UI-изменений и перед переносом мокапа в продакшн-компоненты.

## Google Stitch

[[Google Stitch]] полезен для этапа **от идеи к кликабельному прототипу**.

Что важно:

- не микроменеджерить цвета и кнопки на старте;
- задавать бизнес-задачу и просить несколько направлений;
- режим [[Google Stitch Ideate]] использовать для параллельной генерации концептов;
- дальше переносить удачные варианты в Figma / Lovable / код.

Шаблон:

```text
Design a flow for [user type] who needs to [goal] but struggles with [pain point]. Propose 3 different solutions.
```

## Лендинги и HTML-прототипы

В базе есть готовые промпты:

- [[Промпт лендинга в минималистичном стиле]] — чистый минимализм, Apple/Notion-like, Tailwind через CDN, 4 блока: hero, benefits, pricing, footer.
- [[Промпт pixel-perfect лендинга Green Life]] — anti-break rules для pixel-perfect вёрстки: без absolute positioning для основных секций, без фиксированной высоты, mobile-first, контейнеры, z-index.

Главные правила для AI-генерации лендингов:

- mobile-first;
- `Flexbox` / `CSS Grid` вместо absolute positioning;
- не использовать фиксированную высоту для секций с текстом;
- проверять наложение текста, картинок и z-index;
- просить полный HTML-мокап до внедрения в приложение.

## Effective HTML и визуальные документы

[[Effective HTML skills]] полезен, когда нужен не интерфейс приложения, а автономный визуальный HTML-документ:

- обычные HTML-страницы;
- fullscreen-диаграммы;
- страницы с планами;
- визуальные отчёты и презентационные материалы.

Для клиентских объяснений и архитектурных схем это часто быстрее, чем полноценный frontend.

## Lottie для микроанимаций

[[Lottie skill]] полезен для UI-состояний:

- loading;
- success;
- error;
- empty state;
- onboarding motion;
- небольшие промо-анимации.

Правило: анимация должна объяснять состояние или усиливать UX, а не просто «двигаться, потому что красиво».

## Antigravity Awesome Skills для дизайна

[[Antigravity Awesome Skills]] — installable-библиотека `SKILL.md`-плейбуков для AI coding agents. Для дизайна в вайбкодинге полезна не вся библиотека, а **точечные plugin packs**.

Repo: https://github.com/sickn33/antigravity-awesome-skills

Полезные design-related packs:

| Pack | Для чего |
|---|---|
| `AAS Product Design Studio` | product UI, brand, portfolio, accessibility, визуальная проработка |
| `AAS Web App Builder` | frontend/full-stack web apps, UI-компоненты, современные веб-интерфейсы |
| `AAS Accessibility & Inclusive UX` | WCAG, accessibility-аудит, screen-reader checks, доступный UX |
| `antigravity-bundle-web-designer` | веб-дизайн и визуальная сборка страниц |
| `antigravity-bundle-creative-director` | креативное направление, визуальная концепция, стиль |
| `antigravity-bundle-apple-platform-design` | интерфейсы под Apple-платформы |

Практическое правило: **не ставить весь каталог ради дизайна**. Сначала выбрать узкий pack под задачу: лендинг → Web App Builder / Web Designer; продуктовый UI → Product Design Studio; качество интерфейса → Accessibility & Inclusive UX.

## Open Design

[[Open Design]] — open-source альтернатива Claude Design от Nexu Labs для генерации дизайнов через разных AI-агентов.

Репозиторий: https://github.com/nexu-io/open-design

Что зафиксировано из источника:

- 71 шаблон интерфейсов в виде файлов `DESIGN.md`;
- 19 встроенных skills;
- 5 готовых визуальных стилей;
- поддержка разных экранов и форматов: desktop/mobile;
- задачи: концепты, логотипы, лендинги, презентации, изображения, видео/audio previews;
- интеграции: Claude Code, Codex, Cursor Agent, Gemini CLI, OpenCode, Qwen и другие;
- по текущему README репозитория: 100+ skills, 150 `DESIGN.md` systems, 261 plugins, sandboxed preview и экспорт HTML/PDF/PPTX/MP4.

Важно: перед установкой нужно провести [[Аудит skills|аудит безопасности]], потому что проект ставит skills/plugins/MCP-интеграции в coding agents.

## Где применять

- прототипы лендингов и SaaS-страниц;
- дашборды, CRM-экраны, внутренние инструменты;
- визуальная упаковка AI/IT-кейсов;
- дизайн-системы для вайбкодинг-проектов;
- клиентские презентации и HTML-отчёты;
- проверка «красиво, но непонятно» → фокус на задаче пользователя.

## Чек-лист перед разработкой UI

- [ ] В плане есть отдельная фаза дизайна.
- [ ] Выбраны 2–3 референса или выбран режим «без референсов».
- [ ] Создана дизайн-система / `DESIGN.md` / MasterMD.
- [ ] Сгенерированы 1–2 эталонных мокапа.
- [ ] Сравнены варианты по пользе, а не только красоте.
- [ ] Проверена кириллица в шрифтах.
- [ ] Проверены mobile/tablet/desktop.
- [ ] UI прогнан через браузерную проверку / [[Playwright MCP]].
- [ ] Документация спринта обновлена стилями и компонентами.
