# Emil Kowalski — Design Engineering

Набор из девяти skills от Emil Kowalski для дизайнеров и инженеров, которые делают UI с AI coding agents. Автор — design engineer с опытом в Vercel и Linear; набор вырос из его практики в motion, UI-craft и design decisions.

## Ключевой skill: `emil-design-eng`

Его идея простая: вкус — не произвольное «нравится / не нравится», а натренированная способность видеть, какие решения поднимают качество. Незаметные детали складываются: состояние `:active`, правильная точка происхождения popover, конкретные свойства в transition, а не `transition: all`, осмысленная работа с тенями, границами и скоростью.

Внутри есть практические ограничения для AI-агента:

- сначала решить, нужна ли анимация вообще — у частых действий она обычно только тормозит;
- для enter-анимаций чаще нужен `ease-out`, а не `ease-in`;
- не анимировать keyboard-initiated действия, command palette и другие частые операции;
- popover масштабируется от trigger, модальное окно — из центра;
- у интерактивных элементов должен быть быстрый feedback на нажатие;
- review UI-кода выдаётся таблицей «до → после → почему», а не разрозненным списком.

## Где применять

- Финальная проверка лендинга или product UI после основной реализации.
- Компоненты, где microinteraction влияет на ощущение качества: кнопки, popover, drawer, toast, меню, bottom sheet.
- Выбор UI-библиотеки до начала разработки, чтобы агент не притащил случайную зависимость.
- Сравнение нескольких визуальных вариантов для первого экрана или ключевого блока, когда одному сгенерированному решению доверять нельзя.

## Ограничения

- Это сильный слой craft и motion, но не UX-исследование и не замена пониманию бизнес-сценария.
- Нельзя превращать рекомендации в культ анимации: повторяемые и рабочие действия должны оставаться быстрыми.
- Скиллы полезнее, когда перед ними уже известны пользователь, задача экрана и дизайн-направление; иначе получится декоративная активность без причины.
