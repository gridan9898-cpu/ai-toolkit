# LLM Council — коллегиальный разбор решений

## Что это

`llm-council` — спецификация skill для проверки решений через структурированный «совет» из пяти независимых AI-ракурсов. В основе — подход Karpathy LLM Council: независимый анализ → анонимный peer review → итоговый синтез председателя.

Пять обязательных линз:

| Линза | Задача |
|---|---|
| Contrarian | Ищет фатальные изъяны, риски и неявные предпосылки. |
| First Principles Thinker | Сбрасывает поверхностную формулировку и проверяет, ту ли проблему решаем. |
| Expansionist | Ищет недооценённый upside и соседние возможности. |
| Outsider | Смотрит без контекста и ловит проклятие знания. |
| Executor | Проверяет исполнимость и ближайшее конкретное действие. |

## Как работает

1. До запуска прочитать 2–3 релевантных контекстных файла и нейтрально сформулировать вопрос: решение, ограничения, ставки.
2. Получить пять независимых ответов по 150–300 слов.
3. Анонимизировать их как A–E и провести отдельный peer review: сильнейший ответ, главная слепая зона, общее упущение.
4. Синтезировать вердикт: согласия, конфликты, слепые зоны, рекомендация, **одно первое действие**.
5. Сохранить HTML-отчёт и полный Markdown-транскрипт для повторной проверки решения.

## Когда Данилу применять

- выбор позиционирования, оффера или канала продаж;
- дорогая продуктовая/архитектурная развилка;
- решение о запуске, найме, партнёрстве, смене фокуса;
- pressure-test идеи, когда цена ошибки заметна и есть реальные альтернативы.

Не применять к фактическим справкам, простому выбору без ставки и случаям, где нужен уже execution, а не ещё один круг размышлений.

## Зачем Данилу

Полезно как антидот против двух ошибок: принять красивую идею без столкновения с рынком либо бесконечно готовиться вместо действия. Сильная часть подхода — не пять мнений, а принудительный конфликт перспектив и фиксация одного следующего шага.

## Ограничения и адаптация

- Это **не проверка фактов**: внешние данные, рынок, медицина и техника требуют первичных источников отдельно.
- Пять голосов от одной модели не равны пяти независимым экспертам; различие ролей уменьшает однообразие, но не отменяет общие слепые зоны.
- Нельзя использовать совет как способ отложить решение. Для каждой сессии заранее нужен дедлайн и исполнимый выход.
- Указание исходного skill запускать sub-agents и открывать HTML нужно адаптировать под реальные возможности текущего агента; этот документ — референс метода, а не доказательство, что skill уже установлен и работает в Hermes.
- Полный процесс оправдан только для решений с ценой ошибки. Для обычного разбора достаточно 2–3 критических линз и короткого pre-mortem.
