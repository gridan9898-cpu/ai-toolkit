# Kill AI Slop

Источник: [yetone/kill-ai-slop](https://github.com/yetone/kill-ai-slop) · полевая карта: [killaislop.com](https://killaislop.com) · лицензия Apache-2.0.

## Что это

Практический Agent Skill и dependency-free scanner для web-проектов: он ищет в коде и Markdown признаки шаблонного AI-результата, группирует находки, объясняет риск и предлагает минимальную правку. Репозиторий также содержит интерактивный каталог паттернов «до → после».

Источник описывает сигналы в UI и тексте: градиенты «indigo → violet», glow/glass, чрезмерные скругления и тени, плитки/бейджи/карточки в карточках, плоскую типографику, выдуманные stat-блоки, декоративные маркеры `01/02/03`, emoji-spam и обобщённый AI-copy voice. Основной README говорит о 33 признаках, README skill — о 34; перед применением ориентироваться на текущую taxonomy в установленной версии.

## Какую проблему AI-slop решает

AI coding agent легко выбирает узнаваемые дефолты, потому что они выглядят «дизайнерски» в изоляции. В сумме они стирают иерархию, бренд и доверие: интерфейс становится похож на любой vibe-coded SaaS, а текст — на обобщённую рекламную заготовку.

Принцип skill: сначала принять объяснимое решение о цели, иерархии, акценте и голосе; затем добавлять только осмысленное оформление. Сканер — карта для ревью, не автоматический вердикт: градиент, serif или emoji могут быть намеренным выбором.

## Зачем Данилу

Полезен как отдельный quality-gate после генерации AI-кодом, прежде чем показывать лендинг, CRM-экран, дашборд или клиентский прототип. Даёт предметный список того, что проверить, вместо расплывчатого «выглядит слишком AI», и распространяется на интерфейс и русскоязычный текст.

## Как применять

### AI-кодинг и UI

1. После первой рабочей версии запустить read-only scan по исходникам: `node scripts/scan.mjs <путь-к-проекту>`.
2. Открыть каждый hit и отделить дефолт от защищённого дизайн-решения; не вычищать брендовую палитру или осмысленную иллюстрацию.
3. До правок показать групповой отчёт: `паттерн → file:line → почему → минимальная замена`.
4. Править общие tokens/компоненты, а не размазывать замену по вызовам; после — повторить scan и проверить экран визуально.
5. Намеренные попадания подавлять узким `deslop-ignore` с id правила, а не отключать весь класс проверок.

Для AI coding agent можно установить skill через `npx skills add yetone/kill-ai-slop`, затем дать команду «de-slop this project». Сам scanner не редактирует файлы; skill сначала сканирует, triage-ит и отчитывается, а правки вносит только после согласования групп.

### Тексты

Проверять Markdown, лендинги и UI-copy на декоративный «питчевый» голос: например, конструкцию «не просто X — это Y», бессодержательные усилители, emoji и выдуманные цифры. Замена — конкретное утверждение, которое можно подтвердить, без потери исходного смысла. В репозитории есть пример `rules.ru.mjs` для собственных русскоязычных правил.

## Ограничения

- Это не дизайн-система и не замена брифу, UX-проверке или референсам.
- Code-level hit даёт только повод к ревью: без контекста сканер не знает, что элемент намерен и соответствует бренду.
- Уменьшение количества hits не доказывает качество: нужен визуальный просмотр, а для текста — проверка фактов и задачи читателя.
- Не применять массовую «деслопизацию»: сначала отчёт и согласование, затем маленькие обратимые диффы.

## Вывод Данила

Использовать не как кнопку «сделай красиво», а как финальный разбор дефолтов после того, как уже определены пользователь, цель экрана и visual direction. Для агентских CRM/дашбордов первыми проверять иерархию, плотность данных и ясность copy; декоративные эффекты — в последнюю очередь.
